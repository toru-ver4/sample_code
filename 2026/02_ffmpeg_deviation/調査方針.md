# 調査方針

## 背景

これまで、少なくとも以下の事象を確認した。

* FFmpeg v8.0.1 を使いPNG ファイルから HEVC、AV1 の動画を作ると、エンコード後の Code Value が微妙にズレる
  * ズレ量は僅かだが Rampパターンの特性をグラフにプロットした時に目視で分かるレベル
  * Gamma = 2.2 と 2.4 を間違えた、などのズレ量からは遥かに小さい
  * どちらかというと Limited ⇔ Full の変換時に微妙な係数のズレがあった、みたいな感じのレベル

これを踏まえて以下2点を目標とする調査を行いたい。

### 目標1. ズレが生じるケースの明確化

* 静止画ファイルから動画を作ったせいで生じたのか？
  * 静止画の中には TIFF(整数型) や OpenEXR(浮動小数点) があるが、型に依らずに生じるのか？
* 動画から動画を作るトランスコードの場合でも発生するのか？
  * FFmpeg で ProRes を最終的な配布用に HEVC/AV1 に変換する場合はどうなる？

### 目標2. ズレを防止する方法の明確化

* ソースコードを修正して再ビルドが必要なのか？
* あるいはコマンドライン引数を工夫することで回避可能なのか？

## 調査手順

### Step 1. FFmpeg固有の問題であることを静止画で確認

* FFmpeg のデコーダーが正しいことを確認する
  * DaVinci Resolve で 10-bit の HEVC/AV1 の Endode -> Decode (PNG/TIFF) を行い一致確認
  * FFmpeg で 10-bit の HEVC/AV1 の Encode -> Decode (PNG/TIFF) を行い不一致確認
  * FFmpeg で 10-bit の HEVC/AV1 の Encode -> DaVinci Resolve で Decode して上と同じ結果を確認

* FFmpeg のエンコーダーが間違っていることを確認する
  * DaVinci Resolve で 10-bit の HEVC/AV1 の Encode -> FFmpeg のデコードを行い一致確認
  * FFmpeg で 10-bit の HEVC/AV1 の Encode -> DaVinci Resolve で Decode して不一致を確認

### Step 1. の結果

確認したところ、FFmpeg が間違っているのか、DaVinci Resolve がまちがっているのか判別できなかった。
Encode/Decode を同じソフトで行った場合は誤差は許容範囲内であった。
一方で、Encode/Decode を別々のソフトで行った場合は 4/1023 程度の誤差が生じた。正直、どちらのソフトが間違っているか分からない。

### Step 2. Full/Limited の問題か切り分け

個人的な印象としては、静止画の Full Range を動画の Limited Range に変換する箇所に問題がある気がしている。
そこで、次は FFmpeg の入力データを静止画ではなく、私が作成した yuv ファイルを使ってエンコードを x265.exe で行い、
結果を FFmpeg / DaVinci Resolve でデコードして、どちらが間違っているかをハッキリさせようと思う。

結果は ffmpeg/resolve でデコードしたところ、FFmpeg でおかしなところが見つかった。
確定ではないが、FFmpeg の Limited -> Full 変換に問題がある気がしてならない

### Step 2 の結果

調査の結果、以下のことが分かった。

* Limited <-> Full 変換の部分が怪しい
* レンジ変換の影響が出ないように 自前でI010形式の動画を作り、ffmpeg(libavcodec) でエンコードし、それを de265 で I010 にデコードし、それを自前で確認したところ、これまで観測していたズレ量が確認できなかった
* なので、怪しいのは FFmpeg で full range の静止画データから limited range の yuvデータを作るところ

### Step 3 に向けて

FFmpeg のソースを読んだが、なかなか複雑で自分には理解できなかった。
ここは Codex に色々と頑張ってもらったほうが良いと考えている。

そこで以下の条件を満たすために FFmpeg にどのような修正 or コマンドライン引数が必要かを、Agentモードで調査してもらうことにする。

#### Agent への入力

2026/02_ffmpeg_deviation/ffmpeg_prompt2.md を読んで、その内容に従って作業してください。

目的は、FFmpeg 8.1 ソースコードを解析し、必要なら修正して、
scripts/build_ffmpeg.sh と scripts/encode.sh で生成した yuv420p10le ファイルが
scripts/check_10bit_diff.py で OK になるか確認することです。

参照情報として 2026/02_ffmpeg_deviation/ffmpeg_prompt.md も読んでください。

作業では以下を行ってください。

* FFmpeg ソースコード上で原因候補を特定する
* 修正可能なら最小限のパッチを入れる
* Docker コンテナ内で build_ffmpeg.sh と encode.sh を実行する
* ホスト側で check_10bit_diff.py を実行して OK/NG を確認する
* 変更したファイル、根拠、検証結果を報告する

推測で断定せず、ソースコード上の根拠を示してください。
